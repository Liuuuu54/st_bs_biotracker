## 顯示規則

概覽頁的階段進度讀取已保存的生理時鐘，不推進時間。有限階段以整條寬度表示 `已完成 / 總期`；進度由 0 起算，文字最多兩位小數並標示天或小時，填充比例使用原始數值，限制在 0–100%。超出總期的資料顯示到上限；無固定終點的階段只顯示累計時長，不畫百分比。

月經、產兆、假孕與產程門檻直接共用生理引擎的函式，避免 UI 維護另一份近似公式。[進度投影](../scripts/stage_progress.js)、[生理引擎](../scripts/tools.js)。

## 各階段的起算點與分母

| 階段 | 目前進度 | 總期／分母 | 單位 |
|---|---|---|---|
| 卵泡／排卵／黃體／月經期 | `base.days`，進入該階段後的天數 | 基準 9／2／12／5 × 月經長度係數 × 活力／情壓波動，最少 1 天；共用 `getStageLimit` | 天 |
| 孕早／孕中／孕晚／臨產期 | `base.days`，該階段的等效孕日 | 98／98／63／35；變速影響時間推進，不再重乘分母 | 天 |
| 逾期 | `base.days`，逾期後累計等效孕日 | 沒有固定終點，只顯示時長 | 天 |
| 延產期 | `base.days`，等效孕日減 294 | `extensionUntilDays − 294`；期限缺失或無效則只顯示時長；總期為 0 顯示「延产期限已到」 | 天 |
| 假孕期 | `pregnant.pregnantDays`，實際經過天數；不讀未同步的 `base.days` | `max(1, 84 × 引擎夾限後的妊娠速度)`；共用 `getPseudoPregnancyLimit` | 天 |
| 回歸期 | `wombReturn.totalHours − remainingHours` | 保存的 `totalHours`；缺少時鐘不造分母，零時長顯示「回归已完成」 | 小時 |
| 產兆前驅 | 初始時長減 `prodromalRemainingHours`，最少 0 | `48 × 引擎夾限後的 birthDifficulty`；延後超過初始時長顯示 0，剩餘時間缺失視為剛開始 | 小時 |
| 第一產程 | 已完成 phase 的門檻 + 當前 `effectiveLaborHours`；活躍期加總期 50%，過渡期加 85% | 第一產程完整門檻，包含胎數、分娩難度、自然產經驗；phase 比例 50%／35%／15% | 有效小時 |
| 第二產程 | 當前 phase 的 `effectiveLaborHours` | 該 phase 的實際門檻，含先露胎胎位／胎重；下降與娩出為 60%／40%，多胎間歇至少 0.5 小時；切換 phase 時重新起算 | 有效小時 |
| 第三產程 | 當前 `effectiveLaborHours`；產後觀察加已完成的器官娩出門檻 | 器官娩出 + 產後觀察；共用引擎門檻，分別至少 0.5／2 小時 | 有效小時 |
| 產後恢復 | `base.days`，恢復開始後天數 | 保存的 `bio.recoveryDays`，缺值預設 56；零天顯示「无需恢复」 | 天 |
| 無經期／未激活／未知階段 | 無階段計時 | 顯示「本阶段无计时进度」，不造 1/1 | — |

產程標示「小時」代表有效進度，不能直接當成現實經過時間。宮縮、阻塞及其他條件會影響有效時計的增長。第一、第三產程顯示整階段進度，第二產程顯示當前 phase 的進度，旁邊保留 phase 與胎次標籤。

例如標準人類多胎間歇期的半程顯示 `0.25 / 0.5 小时`，填充 50%；貝拉產後恢復第 10 天顯示 `10 / 56 天`，填充約 17.86%。

## 驗證與重現

新增 12 項回歸測試，檢查月經實際跨階段門檻、妊娠邊界、假孕出口、回歸時計、產程各 phase、分數小時、延期及缺值，並確認投影不修改角色資料。
