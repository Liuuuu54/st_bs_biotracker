## 付費實機（2026-10-08）

### 測試環境

- **宿主與插件**：使用者安裝的 SillyTavern 1.19.0，插件更新到 b3b9b1f。
- **模型**：主連線與插件推演都用 DeepSeek `deepseek-flash`。
- **主模型預設**：使用者自己的「夏瑾 天琴座 V2 Beta 1.0」，推理強度維持 max，每輪約 66–90 秒。
- **進行方式**：測試前備份 `settings.json`。測試卡用 API 匯入，追蹤模型在主模型回覆後自動執行。

### 第一輪

| 項目 | 結果 |
|---|---|
| 從介面把寫實世界存到角色卡 | 通過：存成 `{realisticWorld:true, version:1}`，生效值為開，全域仍是關 |
| 卡上設定格式不合 | 測試卡最初少了 `version`，插件提示「格式不受支持」並拒絕覆寫原資料；這是保護機制，行為正確 |
| 寫實世界的註冊提示 | 開頭有「只有人類」指令；`<bs_race>`、種族名錄、胚型、咒縛都沒送；角色註冊為人類 |
| 寫實世界的追蹤提示 | 不送名錄；資料標記寫實世界 |
| 排卵與受精 | 排卵期滿一天後自然排卵 1 顆。兩次內射都由追蹤模型以 `bsAddSperm` 記錄，精液殘留正確累計，卵在每次推進時間時都有受精判定；這兩輪沒有受孕，在機率範圍內 |
| 高潮排卵路徑（直接呼叫工具） | 性慾推到上限時多排 1 顆，排完性慾歸零 |
| 血族註冊 | 種族欄留空，模型判為 `人类 + 血族` |
| 血族需求 | 送給追蹤模型的是 `{flux, sleep, milk, odor, companionship}`。一天後飢餓、排泄仍為 0，乳意、體味、陪伴照常累積。主模型提示寫明「体质上豁免的普通需求：hunger / excretion；flux 自成一项」 |
| 真實面板 | 極需居中占兩排，在使用者的 iPhone 主題下正常 |

第一輪發現的問題與修正（5ac04ef、e38db09）：

- **高潮排卵從未觸發**：劇情兩次寫角色高潮，追蹤模型都只調低性慾，因為提示從沒說高潮該怎麼表示。1.1.4 的異卵雙胎幾乎都來自高潮排卵，不修的話實際遊玩時雙胎率會接近 0。修正：`bsUpdateCharacterStatus` 新增 `orgasm` 選項，追蹤提示也寫明用法。
- **寫實註冊提示仍送非人類欄位說明**：包括血脈比例、flux、`[血族]人类` 範例、伴生卵、精靈懷孕範例。修正：寫實世界下整行拿掉。
- **年齡落回 15 歲**：角色卡只寫「外表二十多歲」的血族，模型沒填年齡，就落回預設的 15。修正：註冊提示要求年齡必填。
- **臨時鍵空殼**：切卡時留下空的臨時鍵狀態 `80:solo`；v1.1.3 驗證時就看過這個現象。修正：臨時鍵不落盤，載入時清掉舊空殼。

以下三件事不是插件的問題，記在這裡供日後參考：
- 註冊表單的「自訂備註」欄留著使用者先前填的懷孕設定，第一次註冊因此被登記成臨產。
- 直接改聊天狀態而不記快照的話，下次讀取會被舊快照還原；這是測試手法造成的，插件自己的註銷流程會記快照。
- 直接改狀態時，主模型的注入提示不會跟著更新。

兩輪結束後都刪除了測試卡、聊天、追蹤狀態和標籤紀錄，並還原使用者的註冊備註和最後選中的角色。比對結果：

- `settings.json` 的頂層設定、插件設定與 20 筆聊天狀態，都與清理後的備份完全一致。
- 與測試前相比，只多了以下差異，都是正常行為：
