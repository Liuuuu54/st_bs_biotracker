# 主动排出补充：同样的尝试量，一次与分次应等效

本修复补充到同一个混合池 PR，沿用上游 `bsDrainSperm(female, amount)`。**只改已显式启用的 pooled-v1 模式；legacy 默认行为不变。** 不新增持续冲洗、all、按父方定向排出或第二种命令格式。

## 原版哪里不一致？

原版用 `min(1, amount/当前总量)` 算本次排出比例，再按品质修正，并将每条剩余向下取整。因此：

1. 每次向下取整会额外丢弃小数，拆成更多次可能排得更多。
2. 即使去掉取整，单次比例在1封顶，仍会让一次给足努力与分几次尝试不同。
3. 混品质情况下，每次以新的池组成重算初始比例，也不是同一个连续过程。

以下是原上游1.2.1的**真实 `applyToolCall` 调用结果**，不是其他引擎的数据：

| 初始池 | 同刻操作 | 原版剩余 | 连续尝试量方案剩余 |
| --- | --- | ---: | ---: |
| 40，品质4 | amount20一次 | 25 | 25.857864 |
| 同上 | amount10两次 | 24 | 25.857864 |
| 同上 | amount80一次 | 11 | 0 |
| 同上 | amount20四次 | 0 | 0 |
| 20@品质0.25 + 20@品质4 | amount20一次 | 17 | 19.554967 |

此前 fork 的 pooled 分支仅去掉了取整并改用逐次品质，尚保留“单次比例封顶”的近似。本次将这部分也改成连续式，不把此前的局部修补当作完整一致性保证。

## 新机制是什么？

`amount` 表示**绝对排出尝试量/努力**，不是保证实际排出的体积。品质1时努力与实际排出1:1；高品质较难排出，低品质较容易排出。方向沿用上游 `q^(-1/4)`。

将这个努力连续地用于整个池，随着组成变化继续分担，而不是每次命令只取一次初始比例：

```text
以努力a为自变量：
dV_i/da = -(V_i/ΣV) × q_i^(-1/4)
```

实现不需要把努力拆成大量小步：沿用混合池标量求根，把品质权重从自然流失的 `sqrt(q)` 换为主动排出的 `q^(1/4)`。

```text
排净所需努力 A_clear = Σ V_i × q_i^(1/4)

A >= A_clear：实际池清零
否则求唯一z：A = Σ V_i q_i^(1/4) × (1-exp(-z/q_i^(1/4)))
排出后 V_i = 原V_i × exp(-z/q_i^(1/4))
```

例如40、品质4，完全排空需约56.5685努力。尝试20只排约14.1421，剩25.8579；尝试80足以清空。不再需要靠拆成几条命令才能用足同样的努力。

## 不改变什么？

- 操作在当前世界分钟瞬时落账，不自动推进时间，也不暗乘体型。
- 改的只是当前实际残量，不清卵、不重抽随机数、不改累积风险预算或父系快照。
- 失活但已入体的残留仍参与物理排出；未入体的物料不参与。
- 归零contact仍保留，已有胚胎的来源审计/事后避孕关联不会丢。
- 孕期、产后、无卵、空池均可操作；空池返回实际排出0。
- 不自动消耗道具、修改清洁度或宫压；这些效果仍由原有独立操作负责。
- **排出后再推进时间**影响之后的受精机会；**先推进时间发生受精，再排出**保留已经发生的胚胎。主动排出不是撤销受精。

工具返回 `drainResult`，含当前分钟、尝试量、实际前量、实际排出/剩余及逐源明细；精确量不经过显示用的小数舍入。
