## 修正前的重現

**宿主試算一定失敗**：插件把聊天物件直接傳給 `getWorldInfoPrompt`，實機拋出 `messages[depth].trim is not a function`。照宿主格式傳入同一段聊天，則正常回傳約 4.5 萬字的觸發結果。失敗後退回插件自己比對關鍵字。

**後備比對過多**：拿這張卡的舊聊天（各 7 則）模擬，插件掃最近 12 則，宿主預設只掃 2 則：

| 聊天 | 插件後備 | 宿主 |
|---|---|---|
| 2026-09-08 | 23/37 條 | 10/37 條 |
| 2026-09-06 | 18/37 條 | 11/37 條 |

聊天越長，插件的掃描範圍越接近整段對話，關鍵字條目就越接近全發。

**快照**：這張卡的預設把世界書放在 user 訊息裡，快照帶的關鍵字條目和宿主該輪觸發的一致（12 條），所以「使用 ST 預設」拿掉 system 訊息時沒受影響。快照的問題在另外三處：排除名單套不上、回覆裡才觸發的條目不在裡面、追蹤請求在跑時送出下一句會漏抓（插件以全域旗標停止攔截）。

補漏第一次實測多補了 3 條常駐、深度注入的條目（羅希娜/二次解釋、莉莉婭/二次解釋、[mvu_plot]正文輸出格式）。它們的每一行其實都在快照裡，只是宿主合併深度注入時改了空白，整段原文比對不上。改成比對忽略空白、常駐條目一律不補後，用同一份快照重算，只剩路加爾，佛拉斯照樣刪掉。

模式整併只在設定頁確認：重新載入後下拉選單只剩主流與參考，原本選主流的設定不變，排除欄位的提示文字已更新，插件沒有錯誤。

## 評估過但沒採用：試跑重組最新快照

為了讓快照不落後一輪，實驗過用宿主的試跑生成（`Generate('normal', {}, true)`，宿主算 token 時也這樣跑）組出下一輪的完整提示詞。試跑不會走到 EJS 與酒館助手的送出前處理，所以另外用 `EjsTemplate.evalTemplate`（寫入類函式換成不生效）渲染 EJS，用酒館助手的 `getVariables` 加 `YAML` 重現 `format_message_variable`。在這張卡上試跑 66 毫秒、渲染 2 毫秒，50 個 EJS 標籤全部渲染、變數沒被改動，世界書條目也和宿主這輪觸發的一致。

沒有採用，因為快照的價值在於不必認識任何擴充：它抓的是送出前、經過所有擴充處理後的請求。試跑重組只模擬得了 EJS 和酒館助手，小白 X 或之後的新擴充都會漏掉。改為保留快照，只用宿主的世界書 API 補漏與刪除排除條目，不依賴任何擴充。

## 測試中的其他觀察

- **另一個瀏覽器蓋掉資料**：測試期間使用者自己的瀏覽器也開著同一個 SillyTavern，重新載入後測試聊天的註冊資料整份不見，狀態是新建的空白（沒有樓層快照、沒有執行紀錄）。這是 1.1.5 存檔修正說明過管不到的情況：不同瀏覽器或裝置不共享 `localStorage`，互相看不到版本號。關掉那個分頁後重新註冊，之後沒再發生。
- **主流生成等待追蹤**：手動追蹤正在跑時送出訊息，主流請求約 30 秒後才送出；沒有追蹤在跑時 3 秒內。沒有追查是否為刻意設計。
- **手動追蹤逐樓補跑**：手動追蹤跑到一半送出新訊息，它會把新樓層一起補跑，主流還在生成時也會送出追蹤請求。屬於既有行為，這次沒動。
- **主流回覆空白**：推理強度 max、輸出上限 65535 時，DeepSeek 有一次思考了約 11 萬字、正文一個字都沒出。屬於主流預設的設定，與插件無關。
