# 历史消息正则处理

## 处理顺序与流水线设计

历史消息正则处理是基于**楼层独立过滤**与**局部流水线 (Pipeline) + 并行提取**的设计机制：

1. **逐楼层过滤**：系统会依次读取当前历史对话的每一楼层消息，对每一楼的原始文本独立执行正则匹配过滤。
2. **流水线执行与并行提取**：
   - 对于每个楼层，所有规则按设置界面中从上到下的顺序依次处理。
   - **排除 (Exclude) 规则**：以流水线方式执行。每一个排除规则匹配到的内容会被剔除，其过滤后的结果作为下一个规则的输入。这能逐步清洗掉文本中的干扰部分（例如 debug 噪点或格式标记）。
   - **提取 (Extract) 规则**：以并行/非互斥方式从当前已清洗文本中匹配内容。如果配置了多个提取规则，各个规则均作用于相同的“排除后基准文本”进行提取，提取出的所有匹配结果将按规则顺序组合，并使用换行符 `\n` 进行合并，作为最终输出。这样可以避免前一个提取规则因清空其余文本而导致后一个提取规则失效。
3. **最终输出**：
   - 如果该楼层**至少有一个启用的提取规则**且匹配成功，最终输入给分析器的文本将仅包含所有提取规则匹配到的合并内容。
   - 如果**没有启用任何提取规则**，或者有提取规则但匹配全部为空，则输出经过所有排除规则过滤后的最终文本。
4. **宿主隔离**：上述整个正则处理均完全在内存中执行，仅用于送入 LLM 分析器的 Payload 构建，绝对不会污染、改写或损坏宿主（SillyTavern）保存在本地的原始聊天记录。

## 规则选项与配置说明

每个正则规则在 UI 界面中以一行的形式呈现，顺序从左到右：

- **启用复选框 (Checkbox)**：勾选代表启用，未勾选的规则在流水线中将被直接跳过。
- **规则类型下拉框 (Select)**：可以选择 **提取** (Extract) 或 **排除** (Exclude)。
- **正则文本输入框 (Text Input)**：支持以下两种正则表达式书写格式：
  1. 带斜杠和修饰符（flags）的正则表达式字面量：
     ```text
     /<content>(.*?)<\/content>/gs
     ```
  2. 不带斜杠的纯正则表达式文本（默认无修饰符，不区分单/多行）：
     ```text
     <content>(.*?)<\/content>
     ```
- **上移 / 下移按钮 (↑ / ↓)**：改变规则在列表中的先后顺序，进而调整流水线 and 提取组合的优先顺序。
- **删除按钮 (×)**：彻底移除当前正则规则。

### 提取规则的捕获组处理

对于**提取（Extract）**类型的规则：
- 如果正则表达式中**包含捕获组**（如括号 `(...)`），提取逻辑会自动取出**第一个有定义的捕获组**。例如匹配 `/<content>(.*?)<\/content>/gs`，将只保留捕获组中的内容，而自动剥离外层的 `<content>` 和 `</content>` 标记。
- 如果正则表达式中**没有捕获组**，则提取完整匹配的文本（即整个匹配字符串）。
- 如果存在 `g` (global) 修饰符，则会提取并组合所有符合规则的匹配项；如果没有 `g` 修饰符，则仅提取第一个匹配项。
