#### 實測發現並修正

1. **破水後提醒自相矛盾**：只有 `bsPassedTime` 與 `bsExcreteMetabolism` 會重建 `notify.thirdly`。tracker 同一輪先推進時間、後呼叫 `rupture`，下一輪主模型同時看到「破水了」與「尚未破水……禁止描写破水」。現在任何工具改變階段或先露胎膜狀態後都重建提醒，跨日的日記提示保留（[tools.js](../scripts/tools.js)）。
2. **工具名進入主模型提示**：破水、托高、延產與難產警示的原文寫著「必须先调用 bsAssistFetalPosition」「或使用 bsChildbirth」，主模型的伏筆備忘因此出現「须先走 rupture 流程」。主流程提示現在對三欄通知都做改寫，保留禁令與狀態，拿掉指示呼叫工具的句子或分句（[tracker_prompt_context.js](../scripts/tracker_prompt_context.js)）；追蹤模型收到的原文不變。
3. **臀位被寫成頭先出**：胎位文字原為「倒位(↑)」，主模型把臀位的第一胎寫成頭先娩出。改為「头位(头朝下)」「臀位(臀部朝下)」（[tracker.js](../scripts/tracker.js)）；修正後追蹤模型的孕態描述也寫「头位（头朝下）」。
4. **時間先推進使操作被拒**：B 的間歇期使用者外轉第二胎，tracker 先推進 30 分鐘，第二胎已入盆，`rotate` 被拒，正文卻寫成功，之後主模型沿用自己寫的胎位。追蹤規則補上例外：操作發生在時間中途、而推進可能先改變條件時，把 `bsPassedTime` 拆成操作前後兩次。修正後 D、C、E 的操作都在推進前完成，肩難產一輪更拆成兩段。
5. **延產後真實產程停滯**：延產把宮壓歸零，期滿或引產進入產兆前驅時宮壓仍是 0；真實產程每次推進的停滯機率為 1 − 宮壓比例，沒有 tracker 加壓就一直停在第一產程（模擬 2880 小時仍未生）。調試直接進入前驅也一樣（D 的橫位聊天起初宮壓 3）。現在進入產兆前驅時宮壓至少補到自然發動門檻（上限的 66%），離場在 50% 發動的也一併補齊。

6. **使用者敘述比系統快**：A 的使用者寫「孩子滑進我手裡」時，系統才剛進入胎體娩出（0.03／1.21 小時），tracker 沒有同步，要等時間追上，期間正文與狀態不一致。`extract` 的說明補上這個用途：劇情已寫出這一胎自己生下、系統仍在下降或娩出中時直接同步，不改用 `bsChildbirth`；`extract` 走自然娩出流程，產後記為自然產，分娩通知也不再標「经助产拉出」，以免主模型把自然生產改寫成助產。另開聊天在胎體娩出 0.15／0.88 小時時讓使用者寫生下，tracker 先 `extract` 再推進 10 分鐘，直接進入第三產程。

### 測試過程注意

- `settings.json` 整份覆寫：測試期間使用者另開的 ST 分頁曾以舊設定蓋掉測試聊天的狀態，關閉後才正常。
- 內建瀏覽器重載 ST 後 API 可能是未連線狀態，要按連接才能生成；早先的生成 403 是重載前的舊 CSRF token。
- DeepSeek 偶爾回空正文；插件把空白助手樓層視為尚未寫完而等待，重新生成即可。
- 用 `createDefaultFemaleState` 建測試角色時預設年齡是 15，必須先改成成年再生成劇情；本次第一段同房劇情曾在未改年齡時生成，已刪除該兩樓並改為 24 歲重做，記錄的結果都以成年角色為準。
- 直接呼叫工具改狀態時要一併記樓層快照，否則重開聊天會被對齊回快照。
- 費用參考：本日真機測試約 56 次請求、200 萬 token，約 ¥2.12（另 $0.15）；分娩測試另約 55 次請求（含三次空回覆重生成與兩次心理推演）。
- 重載頁面或新開聊天後，tracker 會先結算開場白那一樓，分娩情境的計時因此多一段；判讀時以各回合的工具紀錄為準。
- 用調試工具直接改狀態時，若在真實狀態上推進過頭，就無法再對應已寫的劇情；要先複製狀態再試算，或另開聊天。

CRLF 本身是 JavaScript 合法換行（[ECMAScript 規範](https://tc39.es/ecma262/multipage/ecmascript-language-lexical-grammar.html#sec-line-terminators)）；本次沒有實際 SillyTavern 錯誤訊息，不能由「F5 後恢复」直接判定是換行导致。LF 修正符合專案規則，但未宣稱解掉尚未重現的宿主載入錯誤。
